# 我把“抖音开播提醒”做成了一个 AI 可部署的免费 Serverless 项目

项目地址：[GitHub - CrazysCodes/douyin-live-alert](https://github.com/CrazysCodes/douyin-live-alert)

一句话介绍：把抖音主播主页链接放进配置，服务会定时检查开播状态，并通过飞书机器人私聊提醒你。无需登录抖音，不需要 Chromium，也不必常开自己的电脑。

抖音本身也有开播提醒，但我的实际体验是，它往往不会在主播开播后立刻推送，而是刷了一会儿视频后才收到通知。对于想准时进入直播间的人来说，这段延迟可能刚好错过开场。抖抖先知默认每分钟调度一次，单次主播状态检查通常在数秒内完成，因此一般能在一个轮询周期内发现开播：整体是分钟级提醒，检查过程是秒级的。

最初我只是想在喜欢的主播开播时收到提醒。第一版跑在自己的电脑上：定时打开浏览器、读取抖音页面，再通过企业微信发消息。它能工作，但浏览器进程会膨胀，本地计划任务会弹终端窗口，机器关机后服务也随之停止。

后来我把它改造成了“抖抖先知”：Cloudflare Workers 每分钟触发一次，从 D1 读取到期主播，通过抖音 HTTP 接口获取直播状态，再用飞书机器人私聊通知。整个运行链路不需要 Chromium，也不要求登录抖音。

## 为什么最终选择飞书 + Cloudflare

微信小程序订阅消息存在次数额度，每成功发送一次就消耗一次授权，不适合长期无人值守提醒。企业微信群机器人要求先有群；企业微信自建应用又通常依赖可信出口 IP。个人飞书账号可以通过官方 SDK 的 Device Authorization 流程完成一次扫码授权，拿到自己的 `open_id`，随后由机器人应用发送私聊。Cloudflare Workers 和 D1 则负责免费托管、定时调度和持久化。

## 架构

```text
Cloudflare Cron（每分钟）
  -> D1 选择到期主播并获取调度租约
  -> 有界并发请求抖音 HTTP 接口
  -> 状态机判断 offline -> live / 直播间切换
  -> D1 写入幂等通知事件
  -> 飞书机器人私聊
```

主播以 `sec_uid` 去重，因此多个配置不会产生重复轮询。第一次成功观察只建立基线，不会因为部署时主播恰好在直播就误报。只有从离线变为直播，或直播间 ID 发生变化时才创建事件。事件键在 D1 中唯一，重复 Cron 和 Worker 重试不会重复发信；发送失败会指数退避。

## 最容易踩的坑

1. 抖音网页接口不是稳定的公开契约，需要保留健康检查和持续观测。
2. Serverless 平台的外连并发和子请求数量有限，不能为每个主播无限并行。
3. 飞书机器人发消息需要正确的应用权限和接收人的 `open_id`，不是邮箱，也不是企业通讯录 `user_id`。
4. Cloudflare、飞书和管理接口的密钥都只能进入环境变量或 Worker Secret，不能写进仓库。
5. `wrangler.jsonc` 也可能泄露生产 D1 ID，所以项目公开模板使用占位符，部署时只生成被 Git 忽略的本地配置。

## AI Native 的部署方式

仓库根目录提供 `AGENTS.md`、机器可读的 `config.schema.json` 和 `deploy.manifest.json`。使用者可以把一句部署目标交给能操作终端的 AI，让它先跑测试和 doctor，只询问缺少的配置，再执行迁移、部署、健康检查和主播初始化。流程约束明确写着：未经用户允许不得发送测试通知，也不能通过伪造开播状态验证生产通知。

## 当前状态

项目已经在 Cloudflare 上连续观测，轮询通常在数秒内完成，未发现队列积压和重复通知。`v1.0.0` 首先提供飞书 + Cloudflare 的完整实现，同时保留企业微信群机器人和企业微信自建应用的接入说明。

另外，我也已经实现了微信小程序版本。如果你不想自己部署，可以直接打开微信，搜索“抖抖先知”小程序使用。

## 怎么部署

如果你习惯自己操作，准备一个 Cloudflare 账号和飞书机器人应用，按 README 执行部署脚本即可。项目会创建 D1 数据库、迁移表结构、部署 Worker，并把应用密钥保存为 Worker Secret。

如果你更喜欢让 AI 帮忙，可以把下面这句话连同仓库地址交给能操作终端的 AI：

> 阅读根目录 AGENTS.md 和 docs/ai-deploy.md，运行 npm install、npm test、npm run doctor。不要发送测试通知。根据 config.schema.json 只询问缺少的配置，部署飞书 Cloudflare 版，执行迁移、健康检查并添加 config/subscriptions.json 中的主播。

## 为什么开源

这类小工具的需求很个人，但部署链路往往比代码本身更劝退。我希望这个仓库不仅“代码可见”，还能够让普通用户在 AI 的协助下真正复现。仓库已经包含部署契约、配置 Schema、自动化测试、安全约束和故障排查说明。

如果你也需要长期的开播提醒，欢迎试用、提交 Issue，或者补充其他通知渠道。也欢迎关注抖音接口变化，一起把非官方接口带来的不确定性控制在可观测、可恢复的范围内。

> 本项目是非官方工具，与抖音、飞书、Cloudflare 均无隶属或背书关系。接口可能变化，使用者需要自行遵守相关平台规则。
